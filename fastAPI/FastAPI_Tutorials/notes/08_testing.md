## The Testing Stack

| Tool | Role |
|---|---|
| `pytest` | Test runner + fixture engine |
| `TestClient` | Simulates HTTP requests without a live server |
| `app.dependency_overrides` | Replaces real DB/auth deps with test versions |
| `pytest-asyncio` | Only needed if testing raw `async` functions directly |

---

## The Golden Rule

**Test behavior, not implementation.**

> Given this input + this app state → I expect this output.

If you refactor the internals but behavior is unchanged, tests must still pass. If they don't, your tests are testing *how* not *what*.

## Test Setup (`conftest.py`)

**In my own words:**
`conftest.py` is a pytest-specific file where you define fixtures (reusable setup/teardown). The test DB override is the most critical fixture — it swaps the real DB session for an in-memory SQLite session for the duration of each test.

> pytest automatically discovers and imports fixtures from any `conftest.py` file in the same directory or any parent directory. You never need to explicitly import fixtures from `conftest.py` in your test files — just use the fixture name as a parameter and pytest wires it up.

```python
# Generated by GitHub Copilot
import pytest
from fastapi.testclient import TestClient
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from database import Base
from dependencies import get_db
from main import app

TEST_DATABASE_URL = "sqlite:///./test.db"
engine = create_engine(TEST_DATABASE_URL, connect_args={"check_same_thread": False})
TestingSessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

@pytest.fixture(scope="function")
def db_session():
    Base.metadata.create_all(bind=engine)
    db = TestingSessionLocal()
    try:
        yield db
    finally:
        db.close()
        Base.metadata.drop_all(bind=engine)   # clean slate for every test

@pytest.fixture(scope="function")
def client(db_session):
    def override_get_db():
        try:
            yield db_session
        finally:
            pass

    app.dependency_overrides[get_db] = override_get_db
    with TestClient(app) as c:
        yield c
    app.dependency_overrides.clear()
```

**Context matters:**
- `scope="function"` → fixture runs fresh for every test. Most reliable for DB isolation.
- `scope="session"` → fixture runs once for all tests. Faster but risks test contamination.

## Writing Tests

**Snippet:**
```python
# Generated by GitHub Copilot
from starlette import status

def test_create_todo_success(client):
    payload = {
        "title": "Buy groceries",
        "description": "Milk, eggs, bread",
        "priority": 3,
        "complete": False
    }
    response = client.post("/todos/", json=payload)
    assert response.status_code == status.HTTP_201_CREATED
    data = response.json()
    assert data["title"] == "Buy groceries"

def test_create_todo_missing_title_returns_422(client):
    response = client.post("/todos/", json={"priority": 3})
    assert response.status_code == status.HTTP_422_UNPROCESSABLE_ENTITY
```

## Overriding Auth in Tests

**In my own words:**
Protected routes need a valid JWT. Instead of generating real tokens in tests, replace `get_current_user` with a function that returns a fake user dict — same shape as the real thing.

```python
# Generated by GitHub Copilot
from routers.auth import get_current_user

def override_get_current_user():
    return {"username": "testuser", "user_id": 1, "user_role": "admin"}

@pytest.fixture
def auth_client(client):
    app.dependency_overrides[get_current_user] = override_get_current_user
    yield client
    app.dependency_overrides.pop(get_current_user, None)
```

## Test Naming Convention

```
# Bad
test_login_2
test_todo_endpoint

# Good
test_inactive_user_cannot_login
test_missing_password_returns_422
test_admin_can_delete_any_todo
test_user_cannot_see_other_users_todos
```

**Rule:** the test name should describe what behavior is being verified.

## Gotchas

- `app.dependency_overrides` persists across tests if you don't clear it. Always call `app.dependency_overrides.clear()` in teardown.
- `TestClient` is synchronous even for `async def` routes — no `pytest-asyncio` needed for route tests.
- Separate test DB from dev DB always. Never run tests against a real DB.
- `drop_all` in teardown ensures no leftover data bleeds between tests — critical for `scope="function"`.
