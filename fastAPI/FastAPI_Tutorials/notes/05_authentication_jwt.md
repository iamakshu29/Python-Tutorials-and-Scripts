# FastAPI — Authentication: JWT + OAuth2 Password Flow

<!-- Stack: FastAPI 0.115 | python-jose | passlib[bcrypt] | Python 3.12 -->

---

## The Full Auth Flow (in plain words)

```
1. Client POSTs username + password to /auth/token
2. Server verifies password against bcrypt hash in DB
3. Server creates a signed JWT with user info in the payload
4. Client stores the JWT and sends it in every future request:
       Authorization: Bearer <token>
5. Server decodes the JWT, verifies the signature (using `SECRET_KEY`) and checks `exp` — if tampered or expired, it rejects with 401.
6. Protected routes extract the token, decode it, and get the user
```

---

## Password Hashing with bcrypt

**In my own words:**
Never store plain-text passwords. `bcrypt` is a one-way hash — you can verify a password against a hash, but you can't reverse the hash back to a password. Yes, that's correct: bcrypt embeds a random **salt** into the hash itself, so the same password always produces a different hash string, yet `.verify()` still works because the salt is stored inside the hash and used during comparison.

```python
# Generated by GitHub Copilot
from passlib.context import CryptContext

bcrypt_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# When registering a user — hash before saving to DB
hashed = bcrypt_context.hash(plain_password)

# When logging in — verify what the user sent against the stored hash
is_valid = bcrypt_context.verify(plain_password, stored_hash)
```

**Gotchas:**
- `deprecated="auto"` means passlib will flag hashes made with old/weak algorithms on next login so you can re-hash them.
- The hash includes a random salt — two calls to `.hash("same_password")` produce different strings, but `.verify()` still works.

## Creating a JWT (Login endpoint)

**In my own words:**
The JWT payload (`sub`, `id`, `role`, `exp`) is what gets decoded later by `get_current_user`. The `exp` field is the expiry timestamp — python-jose checks it automatically on decode.

```python
# Generated by GitHub Copilot
from datetime import datetime, timedelta, timezone
from jose import jwt

def create_access_token(username: str, user_id: int, role: str, expires_delta: timedelta):
    payload = {
        "sub": username,          # "subject" — standard JWT claim
        "id": user_id,
        "role": role,
        "exp": datetime.now(timezone.utc) + expires_delta
    }
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)


@router.post("/token", response_model=Token)
async def login(form_data: OAuth2PasswordRequestForm = Depends(), db: DbDependency):
    user = db.query(User).filter(User.username == form_data.username).first()
    if not user or not bcrypt_context.verify(form_data.password, user.hashed_password):
        raise HTTPException(status_code=401, detail="Invalid credentials")

    token = create_access_token(
        username=user.username,
        user_id=user.id,
        role=user.role,
        expires_delta=timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    )
    return {"access_token": token, "token_type": "bearer"}
```

**Gotchas:**
- `OAuth2PasswordRequestForm` expects **form data**, not JSON. Requires `pip install python-multipart`.
- Always use `datetime.now(timezone.utc)` for `exp`, never `datetime.utcnow()` (deprecated in Python 3.12).

## Decoding a JWT (`get_current_user`)

**In my own words:**
`OAuth2PasswordBearer` automatically extracts the Bearer token from the `Authorization` header and passes it as a string to the function. `jwt.decode()` validates the signature and expiry — if either fails, it raises `JWTError`.

```python
# Generated by GitHub Copilot
from fastapi.security import OAuth2PasswordBearer
from fastapi import Depends, HTTPException
from typing import Annotated
from jose import jwt, JWTError

oauth2_bearer = OAuth2PasswordBearer(tokenUrl="auth/token")

async def get_current_user(token: Annotated[str, Depends(oauth2_bearer)]):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username: str = payload.get("sub")
        user_id: int = payload.get("id")
        user_role: str = payload.get("role")
        if username is None or user_id is None:
            raise HTTPException(status_code=401, detail="Could not validate user")
        return {"username": username, "user_id": user_id, "user_role": user_role}
    except JWTError:
        raise HTTPException(status_code=401, detail="Could not validate credentials")

user_dependency = Annotated[dict, Depends(get_current_user)]
```

**Context matters:**
- `tokenUrl="auth/token"` → tells Swagger UI where the login form should POST. This is what powers the Authorize button in `/docs`.
- `oauth2_bearer` only extracts the token. `get_current_user` actually decodes and validates it.

**Gotchas:**
- `algorithms=[ALGORITHM]` is a list, not a single string. Common mistake.
- An expired token raises `JWTError` — caught and returned as 401. No extra expiry check needed.
- `payload.get("sub")` can return `None` if the token was crafted without a `sub` field — always guard with `if username is None`.

## OAuth2 vs Google OAuth (Key Difference)

| | OAuth2 Password Flow | Google OAuth |
|---|---|---|
| **Used for** | Your own login form (username/password) | "Sign in with Google" |
| **Password stored** | Yes (bcrypt hashed) | No (`google_id` only) |
| **Token issued by** | Your own server | Google → you exchange for your JWT |
| **`hashed_password`** | Required | `nullable=True` |

**Context matters (Job Application Tracker):**
Users who sign in via Google have `hashed_password = None`. Always check before calling `bcrypt_context.verify()`.
