# FastAPI — SQLAlchemy Queries (Modern 2.x Style)

<!-- Stack: SQLAlchemy 2.0 | Python 3.12 -->

---

## The Key Shift: `select()` over `db.query()`

**In my own words:**
SQLAlchemy 2.x prefers `select(Model)` + `db.execute()` over the old `db.query(Model)` style. The old style still works but is legacy. Ruff and Pylance warn about it.

| Old (legacy) | Modern (use this) |
|---|---|
| `db.query(User).filter(User.id == 1).first()` | `db.execute(select(User).where(User.id == 1)).scalar_one_or_none()` |
| `db.query(User).all()` | `db.execute(select(User)).scalars().all()` |
| `db.query(User).filter(...).delete()` | `db.execute(delete(User).where(...))` |

## Common Query Patterns

```python
# Generated by GitHub Copilot
from sqlalchemy import select, delete, update
from sqlalchemy.orm import Session

# Get all rows
def get_all_todos(db: Session):
    return db.execute(select(Todo)).scalars().all()

# Get one by ID — returns None if not found
def get_todo_by_id(db: Session, todo_id: int):
    return db.execute(select(Todo).where(Todo.id == todo_id)).scalar_one_or_none()

# Filter by multiple conditions
def get_user_todo(db: Session, todo_id: int, user_id: int):
    return db.execute(
        select(Todo).where(Todo.id == todo_id, Todo.owner_id == user_id)
    ).scalar_one_or_none()

# Create
def create_todo(db: Session, todo_data: dict):
    new_todo = Todo(**todo_data)
    db.add(new_todo)
    db.flush()   # write to DB in-transaction, assigns ID before commit
    return new_todo

# Update
def update_todo(db: Session, todo_id: int, updates: dict):
    db.execute(update(Todo).where(Todo.id == todo_id).values(**updates))

# Delete
def delete_todo(db: Session, todo_id: int):
    result = db.execute(delete(Todo).where(Todo.id == todo_id))
    return result.rowcount   # number of rows deleted — 0 means not found
```

## `scalar_one_or_none` vs `scalars().all()`

| Method | When to use |
|---|---|
| `.scalar_one_or_none()` | Expecting 0 or 1 result. Returns `None` if not found, raises if >1. |
| `.scalar_one()` | Expecting exactly 1. Raises if 0 or >1. |
| `.scalars().all()` | Expecting multiple rows — returns a list. |
| `.scalars().first()` | First result or `None` — no error if there are multiple. |

## Filter Operators

```python
# Generated by GitHub Copilot
from sqlalchemy import select, or_, and_

# Equality
select(User).where(User.email == "a@b.com")

# Multiple conditions (AND by default)
select(Todo).where(Todo.owner_id == 1, Todo.complete == False)

# OR
select(Todo).where(or_(Todo.priority == 1, Todo.priority == 5))

# LIKE (case-sensitive in PostgreSQL)
select(Todo).where(Todo.title.like("%groceries%"))

# ilike (case-insensitive — PostgreSQL only)
select(Todo).where(Todo.title.ilike("%groceries%"))

# IN
select(Todo).where(Todo.priority.in_([1, 2, 3]))

# IS NULL
select(User).where(User.google_id == None)
```

## `db.flush()` vs `db.commit()`

| | `db.flush()` | `db.commit()` |
|---|---|---|
| **Writes to DB?** | Yes, but inside the transaction | Yes, finalizes the transaction |
| **Rollback possible?** | Yes | No (after commit) |
| **When to use** | Need the generated `id` before committing (e.g., FK reference) | Finalize all changes |

**In my own words:**
`flush()` is "send this to the DB but don't finalize yet." `commit()` is "this is permanent." The `get_db` dependency commits for you — you only need `flush()` when you need the DB-assigned `id` mid-route.

---

## Context Matters: `db.query()` vs `select()`

- Both work in SQLAlchemy 2.x.
- `db.query()` is the 1.x "legacy" style — Ruff's `SLF001` and Pylance flag it.
- `select()` style composes better, is type-safe, and supports async drivers.
- Use `select()` for all new code.
